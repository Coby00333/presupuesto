--- A. ARQUITECTURA Y CALIDAD DE CÓDIGO JS -------------------------------------

 1. [rápida] Separar el script embebido (≈80 KB) en app.js, calc.js, pdf.js y
    data.js con <script type="module">. Mantiene un index.html limpio y permite
    trabajar cada parte por separado sin build.
 2. Unificar el estado (SERIE, LIBRES, ESTS, ALBROWS, UNDO/REDO, valores sueltos)
    en un único store con patrón reducer + subscribe; hoy hay fuentes de verdad
    duplicadas (DOM + variables) que obligan a re-leer el DOM en cada calc().
 3. Eliminar innerHTML donde hay datos del usuario (renderLibres, renderMat,
    btn-est-add, btn-mat-add): usar createElement/textContent o escapado para
    evitar romper el HTML si un concepto contiene < > " (y prevenir XSS propio).
 4. Añadir JSDoc + // @ts-check en la cabecera del script: el editor valida
    tipos de GRUPOS, MARCAS y firmas de calc()/totalsFor() sin migrar a TS.
 5. Tests unitarios (Vitest o node:test) de las funciones puras: totalLetra(),
    chipVal(), totalsFor(), rebtSug(), rowsA() (partes mat/mo) — se pueden
    extraer tal cual porque no tocan el DOM.
 6. npm run check: node --check + eslint plano (no-unused-vars, no-undef) +
    los tests del punto 5, como verificación previa a cualquier cambio.
 7. Migraciones de versión de estado: hoy st.v=2/v=3 se ignora; añadir
    migrate(st) que transforme estados antiguos (p.ej. los que aún traen excl)
    y evite perder presupuestos guardados al evolucionar el esquema.
 8. Descargar jsPDF y jspdf-autotable a /vendor y servirlos localmente: la app
    hoy depende de CDN (cdnjs) y sin internet no genera PDF (crítico en obra).
